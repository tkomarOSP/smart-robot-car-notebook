## Artifacts — Charter and Entry Conventions

This package is the notebook's **register of artifacts** for the Smart Robot Car work: the analyses, matrices, exports, diagrams and documents produced about the model. Each entry records what an artifact is, where the real thing lives, and how it relates to the model and to the `model_log_book`.

### What this package holds, and what it does not

This notebook stores knowledge entries (notes, observations, decisions, lessons, routines). It does **not** store typed working files. Those live elsewhere in Cartenza:

| Thing | Where it actually lives |
|---|---|
| Typed working output of a routine (table, yaml, html, json, text) | `workspace-manager` workspace branch |
| Finished, promoted output (FMEA, Pugh matrix, trade study, requirements impact analysis) | `project-artifact-repo` |
| The Capella model and its diagrams | `SmartRoboticCar` repo, `master`, via `capella-fabric` |

So an entry here is the **index card and context** for an artifact, not the file itself. Promotion from a workspace to `project-artifact-repo` is always two explicit steps, never automatic.

### Entry template — one entry per artifact

- **Name and type:** e.g. trade study, FMEA, requirements trace table, exported diagram
- **Location:** server, repo/branch, package and artifact id, plus a viewer link when one exists
- **Purpose:** the question it answers or the decision it supports
- **Model basis:** which phase(s) and elements it was derived from, and the model state (commit or date)
- **Status:** draft / reviewed / promoted / superseded
- **Related entries:** ids of `model_log_book` entries (changes, reviews) that it supports or that invalidate it
- **Author / date**

### Conventions

- One entry per artifact. When an artifact is revised, add an addendum to its entry rather than creating a second one, so the history stays in one place.
- When a model change makes an artifact stale, say so in that artifact's entry and cite the `model_log_book` entry that caused it.
- Write the entry **after** the artifact exists and cite the real ids it received; numbers are per package and cannot be predicted.
- Never put credentials in an entry; use `{{GITHUB_PAT}}` if a placeholder is ever needed.
