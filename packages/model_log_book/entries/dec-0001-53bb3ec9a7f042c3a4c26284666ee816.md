## Decision — Drop `Restore Defaults` from the IR Remote capability set

**Decided by:** the model owner, 2026-11-05, in chat ("let's drop the restore defaults").
**Context:** `model_log_book/obs-0002` proposed renaming `Restore Defaults` (SA capability, `7a5f4bce-ef81-41d3-b0fb-505c35ea14b7`) to `Restore Default Line-Tracking Threshold`, provisionally, because its current meaning was unclear.

**Decision:** `Restore Defaults` is dropped from the IR Remote capability set. It is removed from the rename proposal, and the capability is no longer wanted in this set.

**Status:** DECIDED, NOT APPLIED. The model is unchanged (commit `d6654d6`). Two points are still open:
1. **Intent:** whether "drop" means delete the capability from the model, or only leave it out of the rename and untouched. To be confirmed with the owner.
2. **Mechanics:** whether `apply_model_patch` can delete a capability is not stated in the Handbook; capella-fabric's own `instructions` are authoritative. If it can't, the deletion is done in the Capella desktop editor. Either way, before deleting, check what references the capability (involved functions, functional chains, diagrams, requirements, trace links), which needs a reconnected model session; the earlier GitHub authorization has expired.

**Consequence to note:** the manual's key 5 (restore the default line-tracking threshold, see `artifacts/note-0002`) is then covered by no capability. That is acceptable only if restoring the threshold is deliberately out of scope. Otherwise a `Restore Default Line-Tracking Threshold` capability would still be needed, alongside the already-proposed `Reduce Line-Tracking Threshold`.

**Effect on the rename set in `obs-0002`:** the `Restore Defaults` row is withdrawn; all other proposed names stand.


**References:** `obs-0002-a4ac28786f144542b2c2139b529d5532`
